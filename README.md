## Инструкция по запуску

### 1. Установить зависимости
```bash
npm install
npx playwright install
```

### 2. Запустить приложение (в отдельном терминале)
```bash
npm start
```

### 3. Запустить тесты
```bash
# Все тесты во всех браузерах
npm run test:e2e

# Только в Chromium
npx playwright test --project=chromium

# С UI режимом (удобно для отладки)
npm run test:e2e:ui

# Посмотреть отчёт после запуска
npm run test:e2e:report
```

## Архитектура и подход

### Page Object Pattern
Выбран **Page Object Pattern** как наиболее подходящий для данного приложения:
- Все локаторы сосредоточены в `tests/pages/todo.page.ts`
- Тесты в `todo.spec.ts` используют только методы Page Object, не работая напрямую с локаторами
- При изменении CSS-классов или структуры HTML достаточно обновить только Page Object

### Работа с асинхронным API
- Увеличены `actionTimeout` и `navigationTimeout` с учётом задержки JSONPlaceholder до 2 секунд
- Отключена параллельность тестов (`workers: 1`) — API может возвращать непредсказуемые ID при параллельных запросах
- Используется `waitForSelector` при загрузке страницы для ожидания данных из API

### Особенности JSONPlaceholder
- POST всегда возвращает `id: 201` — учтено в тест-кейсах и баг-репортах
- Данные не сохраняются между сессиями — TC-10 проверяет это поведение явно
- PUT/DELETE работают с любыми ID — не тестируем несуществующие ID как ошибку

## Сложности при выполнении

1. **Коллизия ID при добавлении задач** — JSONPlaceholder всегда возвращает `id: 201` для новых задач через POST. Это создаёт проблему при редактировании нескольких добавленных задач подряд (описано в BUG-02).

2. **Задержка API** — ответы от JSONPlaceholder могут приходить с задержкой до 2 секунд, поэтому в некоторых тестах добавлен `waitForTimeout` и увеличены таймауты в конфиге.

3. **Отсутствие data-testid атрибутов** — в HTML нет специальных атрибутов для тестирования, локаторы строятся по CSS-классам, что менее стабильно. В продакшн-проекте рекомендуется добавить `data-testid`.
